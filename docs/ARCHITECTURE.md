# 架构与边界

插件由三部分组成：`scripts/registry.py` 管理持久状态；`hooks/dispatch.py` 响应宿主事件；`skills/use-local-tools/SKILL.md` 指导模型使用能力。

## 发现和刷新

用户先指定扫描根目录。注册器只读取已知类型的项目元数据，生成候选；README 中即使带有命令，也不会在扫描过程中执行。没有为某个工具写死名称或下载器适配器。

`SessionStart` 扫描清单。`UserPromptSubmit` 再扫描，然后把当前任务通过 stdin 交给检索；最多选出 12 个候选，摘要 JSON 约束在 11,000 字符以内。模型看到的是名称、位置、描述、状态等摘要，需要时再读 `inspect` 和项目用法。

刷新是有界重扫与元数据指纹比较，不是文件系统增量索引。默认深度 2，可配置 0–4；最多 64 个扫描根、单次 4,000 个访问目录。跳过符号链接、虚拟环境、依赖目录、非普通文件及大于 64 KiB 的元数据。

Hook 内部单个注册器进程超时 6 秒，宿主 Hook 超时 15 秒。扫描失败会提示清单可能过时，不阻止原任务。大目录、慢磁盘、锁竞争仍可能触发限制。

## 共享状态

多个本机会话通过同一数据目录共享 `registry.json`。写入使用进程锁、临时文件和原子替换；只读操作加载完整的已提交快照，不申请写锁。读者可能拿到刚提交前的旧版本，输出中的 revision 可用于区分。

用户登记的描述、能力和调用信息会保留，不被后续 README 刷新直接覆盖。损坏的数据库报错，不会默默覆盖成空库。每条记录保存最多 12 个历史事件。

`candidate` 是已发现但未登记入口；`configured` 是登记了入口且基础检查通过；`unavailable` 是位置、入口或必要环境等检查失败。当前没有产生 `verified` 状态的接口。`doctor` 不运行工具，也不检查产物、Python 依赖、参数或登录有效性。

## 执行与信任

项目元数据以不可信数据提供，JSON 中的 `<>&` 转义避免伪造上下文边界。Hook 不执行候选项目；实际工具调用依旧由模型通过宿主的正常工具和权限完成。

这些措施缩小元数据造成误导的机会，但不是对模型提示注入免疫的保证。来自 README 的任何要求都不能覆盖用户任务或授予权限。

审计记录事件、时间、会话与轮次 ID、清单版本、候选 ID、摘要长度和哈希。Hook 不把用户提示原文写进自身审计，也不自动采集环境变量值；用户自行写入卡片描述或 argv 的秘密不会被全面识别。宿主本身仍可能按其设置记录对话。

审计日志尚无轮转；Windows、分布式同步、向量检索和系统包管理器适配都未实现。

## 为什么仍保留 Skill

Hook 能在宿主事件触发时刷新清单，不必先由模型想起某个技能。Skill 则负责说明怎样解释候选、读取用法、验证结果及登记新安装的工具。它们承担不同工作。

Skill 提供使用指导，Hook 提供事件触发入口。两者都不能保证模型最终采用某个工具；是否复用需要看实际执行和产物。
