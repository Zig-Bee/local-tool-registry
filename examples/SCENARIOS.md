# 使用示例

以下是任务写法与适用条件，是否采用已有工具以实际执行为准。

## CSV 转 Markdown 表格

前提：扫描范围内已有能处理 CSV 的表格工具，且具备可用的运行环境。

> 请将 measurements.csv 转成 GitHub Flavored Markdown 表格，保存为 report.md。第一行作为列名，保留原列顺序与全部数据行，不增加行号。完成后记录实际执行的处理命令。

## 原始磁盘报告转 JSON

前提：已有能解析相应磁盘报告格式的工具。

> 请将 storage.txt 中的磁盘使用报告转成 JSON，保留设备、容量、已用空间和挂载点。说明各字段的单位，并保存为 storage.json。

## 发视频链接让模型分析

> 请看看这个视频，整理它的主要观点、操作步骤和适用条件。

可能的处理流程：识别链接平台 → 查找适配的本地获取工具 → 阅读用法与限制 → 获取可分析素材 → 分析内容。

插件只负责发现已有能力和支持后续选择。下载器不等同于视频分析器；登录、下载、文件完整性及视频分析都取决于实际工具和宿主能力。

## 新增工具后

把带 README 或受支持项目配置的工具放进扫描目录，下次成功扫描会更新候选。没有可用说明时，可以登记 [能力卡](tool-card.json)。

放到范围外时，重新运行安装器追加目录。扫描不会安装项目依赖。

## 没有合适工具时

直接描述任务即可。候选清单供模型判断，并不要求强行使用已有工具；如果没有适用项目，模型可以采取其他可用方法。
